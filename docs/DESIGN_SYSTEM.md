# TimeSheetPro — Material 3 Expressive

Цель: сохранить таймер, записи, заказчиков, настройки и финансовые сценарии; объединить оформление в сдержанную систему. Крупные акценты относятся к текущему времени и главному действию. Данные и настройки остаются компактными.

## Источники и реализация

- [Material 3 Expressive](https://m3.material.io/blog/building-with-m3-expressive)
- [Material 3 в Compose](https://developer.android.com/develop/ui/compose/designsystems/material3)
- [Версии Material3](https://developer.android.com/jetpack/androidx/releases/compose-material3)
- [Доступность](https://developer.android.com/codelabs/starting-android-accessibility)
- [Производительность Compose](https://developer.android.com/develop/ui/compose/performance)

Используются Material3 1.5.0-alpha28, Compose BOM 2026.09.00 и compileSdk 37. Целевой Android остаётся API 36, минимальный — API 24. Expressive не требует Android 17 на устройстве: API 37 нужен для компиляции зависимостей.

## Роли

| Область | Источник | Применение |
| --- | --- | --- |
| Цвет | `Theme.kt` | Светлая и тёмная палитры, уровни поверхностей, контуры, контейнеры и содержимое |
| Статусы | `LocalStatusPalette` | Оплачен, выставлен счёт, не оплачен; текст сохраняется вместе с цветом |
| Текст | `Typography` | Роли display/headline/title/body/label на Google Sans с кириллицей; системный шрифт на API 24–25 |
| Числа | `LedgerStyles` | Табличные цифры Google Sans для сумм, длительности и циферблата; компактный размер для крупного системного шрифта |
| Геометрия | `AppShapes` | Скругления 4 / 8 / 12 / 20 / 28 dp; круг для отдельных круглых элементов |
| Отступы | `AppSpacing` | Основная шкала 4 / 8 / 12 / 16 / 20 / 24 / 32 dp |
| Размеры | `AppSize` | Область действия 48 dp, главное действие от 56 dp, пределы и толщина циферблата |
| Кнопки | `AppButton` | Официальная Expressive-анимация формы, семантика Material, отключённое состояние и ripple |
| Движение | `MaterialTheme.motionScheme` | Spatial для перемещений, effects для прозрачности; системный масштаб анимации обрабатывает Compose |
| Каталог | `ComponentCatalog` | Preview обеих тем и шрифта 200%, состояния полей, кнопок, фильтра и статусов |

Стандартные Card, OutlinedTextField, FilterChip, Switch, AlertDialog и ModalBottomSheet используют общую Material-тему. Новые обёртки нужны только там, где есть повторяемое прикладное поведение; не следует дублировать весь API Material.

Основной, вторичный и третичный акценты принадлежат лавандовой семье; розовый исключён из оформления. Цвета оплаты остаются зелёными, янтарными и красными, с текстовой подписью.

Фиксированные цвета клиентов — пользовательские данные, а не цвета темы. Их значения не изменяются. Виджет и уведомление получают соответствующие светлые/тёмные ресурсные цвета по системной теме; принудительный режим темы внутри приложения на системные поверхности пока не распространяется.

## Поведение

- Сохраняются четыре пункта нижней навигации и текущие переходы.
- Завершение таймера — обычное действие сохранения, удаление — действие ошибки/опасности.
- Секундное состояние читается только в LiveTimerDial. Сводка пересчитывается при изменении записей или местной даты.
- Запрос экспорта защищён модальным состоянием загрузки; генерация и запись файла выполняются вне главного потока.
- Превью фото оплаты декодируется в фоне с ограничением разрешения; оригинал не изменяется.
- Чек открывается касанием миниатюры с подсказкой расширения. Полноэкранный просмотр использует ту же тему, общий заголовок и действия 48 dp; поддерживает увеличение 100–500%, перемещение и сброс. Декодирование выполняется на IO: до 1024 px для миниатюры и 2048 px для просмотра. Границы перемещения вычисляются по фактическому изображению после ContentScale.Fit и повторно ограничиваются при смене размера окна; до загрузки изображения увеличение отключено. URI и исходный файл не изменяются. После пересоздания окна просмотр располагается поверх исходной формы.
- Крупный текст проверяется отдельно: минимальные высоты кнопок не ограничивают рост содержимого.

## Правила компонентов

`AppAction` задаёт смысл действия: `Primary` — основное, `Secondary` — outlined, `Tonal` — вспомогательное заметное, `Quiet` — текстовое. `Destructive` и `DestructiveQuiet` используют цвета ошибки только для удаления или отказа от сохранения. Экспорт, подтверждение оплаты и завершение таймера — обычные основные действия.

`AppSheetHeader` и `AppIconAction` обеспечивают явное закрытие, область 48 dp и подпись. `AppChoiceSheet` использует radio для единственного выбора; фильтры — стандартные chips. `AppFormSheet` разворачивает и прокручивает длинные формы. Выбор формата экспорта имеет выбранное состояние, которое не выражается только цветом.

`AppCheckboxRow` объединяет подпись, пользовательскую цветную метку и чекбокс в одну переключаемую строку от 48 dp. Родитель использует `toggleable` с ролью Checkbox; вложенный стандартный Checkbox имеет `onCheckedChange = null`. Один фокус озвучивает подпись и состояние. Компонент применяется к заказчикам в фильтрах и колонкам экспорта выбранных записей. Это соответствует [рекомендации Android по выбору в строках](https://developer.android.com/develop/ui/compose/accessibility/api-defaults).

Панель «Отчёт по выбранным» использует общий заголовок с закрытием и `AppLedgerSummary`: при недостатке ширины или увеличенном шрифте время и сумма располагаются вертикально.

`AppFormActions` размещает действия формы в FlowRow: кнопки делят доступную строку или переходят на отдельные строки, сохраняя целые слова в подписях. Компонент используется в формах заказчика, сессии, ручных записей, редактирования, оплаты и в фильтрах. Панель массового выбора также переносит группы действий и не имеет фиксированной высоты.

Успех экспорта обозначается одной поверхностью «Отчёт готов» с действиями сохранения и отправки; дублирующее всплывающее сообщение убрано.

`AppClientField` — активное поле выбора с цветной меткой и стрелкой; оно не использует семантику отключённого текстового поля. `AppClientPickerSheet` объединяет выбор заказчика во всех формах: одна группа radio, полное название и область строки от 56 dp. Поля форм используют `MaterialTheme.shapes.medium`.

Выбор статуса одной или нескольких записей использует тот же `AppChoiceSheet`. При разных исходных статусах в массовом выборе ни один radio не отмечен. Все изменения статусов выполняет прежний ViewModel.

`keepFocusedFieldVisible` повторяет прокрутку поля после появления клавиатуры через `BringIntoViewRequester`; учитывается фокус вложенного редактора `OutlinedTextField`. Доступность поля имени в горизонтальном режиме проверяется с обязательно открытой IME и сравнением границ. Пустой список заказчиков содержит пояснение. Нулевая сумма — нейтральная подсказка, а не ошибка: правила сохранения и расчёты остаются прежними.

`AppInfoMessage` оформляет нейтральные пояснения: поверхность `surfaceContainerHigh`, декоративная иконка Info 24 dp, текст `bodySmall`, отступы 16/8 dp. Сохранение сессии, редактор и ручная запись используют одинаковую подсказку о нулевой сумме; текст не утверждает, что нулевая ставка запрещена.

Окно отказа открытия базы использует `safeDrawingPadding`, общие отступы и прокрутку. Абзац ограничен токеном `AppSize.messageMaxWidth = 560 dp`, чтобы на широком экране текст не растягивался от края до края. Цвета текста и поверхности берутся из темы; действий, предлагающих сброс данных, нет.

Первый кадр Activity ждёт открытия базы и чтения сохранённой темы в `lifecycleScope` на IO. Ошибка чтения разрешает показ окна защиты данных. Системная стартовая поверхность сохраняется через `OnPreDrawListener`, как в [рекомендации Android для асинхронного чтения настроек](https://developer.android.com/develop/ui/views/launch/splash-screen). При действиях уведомления/виджета существующая Activity используется повторно; входящее действие не заменяет её исходный launch Intent. Новые ключи настроек и поля Room не добавлены.

Значок приложения — векторный секундомер на лавандовом фоне, с адаптивным и монохромным вариантами. В шторке рабочее время расположено над длительностью пауз, а две круглые кнопки находятся справа. Это же содержимое используется в обеих высотах системного уведомления. На экране блокировки Android 17 при доступных Live Updates система показывает рабочее время и паузы отдельными счётчиками в развёрнутой карточке.

При выбранном заказчике сессия сохраняется сразу. На разблокированном телефоне кнопка открывает «Записи» с подтверждением, длительностью и переходом к редактору сохранённой записи. С экрана блокировки сохранение проходит без разблокировки, а подтверждение открывается при следующем входе в приложение.

Минимальная высота виджета — 96 dp: учитывается внутренний отступ Android AppWidgetHost, чтобы 48 dp действия и строки времени не обрезались. Статусы краткие: «Таймер готов», «Идёт запись», «На паузе». В низком диалоге времени с клавиатурой действия располагаются сбоку от полей; в остальных случаях закреплены ниже прокручиваемого содержимого.

Длинные названия и крупные суммы переносятся. Сводка переходит от колонок к вертикальным метрикам по доступной ширине. При увеличении шрифта на узком экране навигация показывает иконки с полными подписями доступности и подсказками. В горизонтальном таймере циферблат и управление находятся рядом. Поля времени переходят к компактному вводу на низком экране или при шрифте выше 130%; в обычном режиме доступны циферблат и клавиатура. Это два стандартных варианта [Material time picker](https://developer.android.com/develop/ui/compose/components/time-pickers).

Вложение чека выбирается через Android OpenDocument с постоянным разрешением на чтение. Исходный URI хранится прежним способом. Превью декодируется вне главного потока до 1024 px; загрузка и недоступный файл имеют явные состояния. Для JPEG учитываются восемь EXIF-ориентаций, включая отражение: преобразуется только bitmap для показа, оригинал не изменяется. Метаданные читаются через InputStream официальным [AndroidX ExifInterface 1.4.2](https://developer.android.com/jetpack/androidx/releases/exifinterface). Зависимость добавлена для совместимого чтения ориентации: Lint предупреждает о старой платформенной реализации; остальные версии сохранены.

Результат резервного копирования показывает имя файла отдельной строкой `bodySmall` с вторичным цветом; оно не конкурирует с основными действиями. Короткий заголовок «Ошибка копии» и русские сообщения формата/версии сохраняют читаемость при 200%. Предупреждение восстановления явно сообщает о замене данных и об исключённых отчётах/вложениях/таймере.

## Печатный счёт

PDF — отдельная поверхность A4 с размерами в типографских пунктах. Лавандовый акцент, текст, вторичный текст, разделители и спокойная заливка строк берутся из `LightColorScheme`; бумага остаётся белой независимо от темы экрана. Заголовки используют обычный регистр, числовые значения — моноширинное начертание, итог находится на отдельной строке.

Названия и комментарии переносятся в своих колонках. Высота строки определяется содержимым; особенно длинный комментарий продолжается на следующей странице с повтором заголовков таблицы. Сводка заказчиков в шапке ограничена тремя строками с явным многоточием, полные названия остаются в строках таблицы. Расчёты, сохранённые суммы и формат длительности прежние. Для определения переносов применяется [Android StaticLayout](https://developer.android.com/reference/android/text/StaticLayout.Builder), документ создаёт прежний Android PdfDocument.

## Визуальная приёмка

Эталоны заполненных экранов находятся в `app/src/test/screenshots/design-system`: две темы, портрет, горизонтальная ориентация и шрифт 200%. `Verify.cmd` сравнивает результат с эталонами через `verifyRoborazziDebug`; он не перезаписывает их. `RecordSnapshots.cmd` — отдельная явная команда для обновления после осмотра. Наличие эталона не означает приёмку всех окон.

Настоящие окна и действия проверяются `VisualAuditTest` на отдельном пакете `com.example.preview`. Повторяемый запуск: `tools/Run-VisualAudit.ps1`; снимки: `app/build/outputs/visual-audit`. Реестр покрытия и ещё не пройденные состояния находятся в `docs/VISUAL_AUDIT.md`, фактические результаты — в `docs/VERIFICATION_STATUS.md`.

Проверка шрифта 150/200% и горизонтальной ориентации: `tools/Run-AdaptiveAudit.ps1`. Тест задаёт ориентацию самой Activity и проверяет её конфигурацию; одного значения системной настройки поворота недостаточно. После прохода сценарий возвращает исходный масштаб шрифта и настройки вращения.

Восемь эталонов настоящих панелей выбора (валюта, округления и тема в двух темах) находятся в `app/src/androidTest/assets/visual-goldens`. Тест захватывает окно Android и сравнивает пиксели самой панели с эталоном; системные панели и изменяемое состояние под модальным окном исключены. Обычный запуск не обновляет эталоны. Для этих сравнений нужны API 36, плотность 420, портрет, 1080×2424 и масштаб шрифта 100% на выделенном AVD.
